Worksite Report API demo

Copy each command into one terminal, in order. Mark claims progress on a task, Linda approves it, and only then does the task's official progress change.

What to watch: Build ground-floor walls

Black is approved progress, the official figure. Yellow stripes are Mark's claim.

Before
40% approved
Step 2: Mark claims 60%
40% still approved
Step 3: submitted
40% waiting for Linda
Step 4: Linda approves
60% now official

Main flow

About three minutes. Every write sends an Idempotency-Key and, after the first save, the report's version.

For a clean start, before the interview: docker compose down -v && docker compose up --build -d. This removes earlier reports. To rehearse again without it, pick another work date above.

Set the variables

Run once. Every command below uses these names. RUN makes each rehearsal's keys new.


    

  


  

    
1

    

      
Mark views the worksite
Mark · Foreman

      
Only Mark's two tasks. Walls at 40. Henry's task is hidden from him.

      
curl -s "$BASE/worksites/$SITE" \
  -H "X-Actor-Id: $MARK" -H "X-Actor-Role: FOREMAN" | jq

    

  


  

    
2

    

      
Mark saves a draft: walls at 60%
Mark · Foreman

      
DRAFT, version 1. The report ID is kept in REPORT_ID for the next steps.

      
REPORT=$(curl -s -X PUT "$BASE/worksites/$SITE/reports/$DAY" \
  -H "X-Actor-Id: $MARK" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: mark-save-$RUN" -H "Content-Type: application/json" \
  -d '{"items":[{"taskId":"00000000-0000-4000-8000-000000000202","reportedProgress":60}]}')
echo "$REPORT" | jq; REPORT_ID=$(echo "$REPORT" | jq -r .id)

    

  


  

    
3

    

      
Mark submits
Mark · Foreman

      
SUBMITTED, version 2, one transition recorded. The walls are still 40: a claim is not progress yet.

      
curl -s -X POST "$BASE/reports/$REPORT_ID/submit" \
  -H "X-Actor-Id: $MARK" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: mark-submit-$RUN" -H "Content-Type: application/json" \
  -d '{"version":1}' | jq

    

  


  

    
4

    

      
Linda approves
Linda · Site supervisor

      
APPROVED, version 3. Report and task change in one transaction.

      
curl -s -X POST "$BASE/reports/$REPORT_ID/approve" \
  -H "X-Actor-Id: $LINDA" -H "X-Actor-Role: SITE_SUPERVISOR" \
  -H "Idempotency-Key: linda-approve-$RUN" -H "Content-Type: application/json" \
  -d '{"version":2}' | jq

    

  


  

    
5

    

      
Linda checks the tasks
Linda · Site supervisor

      
Walls now 60. Linda sees all three tasks.

      
curl -s "$BASE/worksites/$SITE" \
  -H "X-Actor-Id: $LINDA" -H "X-Actor-Role: SITE_SUPERVISOR" \
  | jq '.tasks[] | {name, approvedProgress}'

    

  


  
On request: reject and resubmit

  
Henry reports Install electrical at 10%. Linda rejects it with a reason, Henry corrects it to 5% and resubmits, and Linda approves. Needs step 0 only.


  

    
R1

    

      
Henry saves and submits
Henry · Foreman

      
SUBMITTED, version 2. The ID is kept in HENRY_REPORT_ID.

      
HENRY_REPORT_ID=$(curl -s -X PUT "$BASE/worksites/$SITE/reports/$DAY" \
  -H "X-Actor-Id: $HENRY" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: henry-save-$RUN" -H "Content-Type: application/json" \
  -d '{"items":[{"taskId":"00000000-0000-4000-8000-000000000203","reportedProgress":10}]}' | jq -r .id)
curl -s -X POST "$BASE/reports/$HENRY_REPORT_ID/submit" \
  -H "X-Actor-Id: $HENRY" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: henry-submit-$RUN" -H "Content-Type: application/json" \
  -d '{"version":1}' | jq

    

  


  

    
R2

    

      
Linda rejects with a reason
Linda · Site supervisor

      
REJECTED, version 3. The reason is in the last transition. Electrical stays at 0.

      
curl -s -X POST "$BASE/reports/$HENRY_REPORT_ID/reject" \
  -H "X-Actor-Id: $LINDA" -H "X-Actor-Role: SITE_SUPERVISOR" \
  -H "Idempotency-Key: linda-reject-$RUN" -H "Content-Type: application/json" \
  -d '{"version":2,"reason":"Conduit laid, no wiring pulled yet"}' | jq

    

  


  

    
R3

    

      
Henry corrects to 5% and resubmits
Henry · Foreman

      
The edit keeps it REJECTED, version 4. The resubmit makes it SUBMITTED, version 5.

      
curl -s -X PUT "$BASE/worksites/$SITE/reports/$DAY" \
  -H "X-Actor-Id: $HENRY" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: henry-edit-$RUN" -H "Content-Type: application/json" \
  -d '{"version":3,"items":[{"taskId":"00000000-0000-4000-8000-000000000203","reportedProgress":5}]}' | jq
curl -s -X POST "$BASE/reports/$HENRY_REPORT_ID/submit" \
  -H "X-Actor-Id: $HENRY" -H "X-Actor-Role: FOREMAN" \
  -H "Idempotency-Key: henry-resubmit-$RUN" -H "Content-Type: application/json" \
  -d '{"version":4}' | jq

    

  


  

    
R4

    

      
Linda approves and checks
Linda · Site supervisor

      
APPROVED, version 6. Electrical is now 5, and the history keeps the rejection and its reason.

      
curl -s -X POST "$BASE/reports/$HENRY_REPORT_ID/approve" \
  -H "X-Actor-Id: $LINDA" -H "X-Actor-Role: SITE_SUPERVISOR" \
  -H "Idempotency-Key: linda-approve-henry-$RUN" -H "Content-Type: application/json" \
  -d '{"version":5}' | jq '{status, version, transitions}'
curl -s "$BASE/worksites/$SITE" \
  -H "X-Actor-Id: $LINDA" -H "X-Actor-Role: SITE_SUPERVISOR" \
  | jq '.tasks[] | {name, approvedProgress}'
